# Награды: переработка системы достижений

> Заменяет концепцию из `docs/achievements-rework.md`. Тот реворк оставлял гарму как
> награду и сознательно делал «минималистичные карточки»; здесь всё наоборот —
> награда это знак, а не валюта, и подаётся она как трофей.
>
> Ветка: `feat/achievements-rework`.
> **Статус: концепция согласована, каталог определён. Дальше — реализация по этапам.**

## Зачем

Прошлая система (21 группа, `1/50/500/2500/10000`) — это беговые дорожки: их
накручивает любой и рано или поздно получает каждый. Редкость ничего не значит,
награда (гарма) превратила достижения в кран валюты, а «время на сайте» и
365-дневные серии — в тёмные паттерны. Человеческого суждения в системе нет,
поэтому она и читается как ИИ-слоп.

Новая система — про **статус**, а не про счётчики.

## Принципы

1. **Награда — знак, не валюта.** Гарму за достижения не даём. Никакого
   `reward_type`/`reward_value` в уровнях.
2. **Два вида.** *Вехи* — автоматические, зарабатываются делом. *Награды* —
   ручные, их вручает модератор/админ за вклад и события. Ручные — престижнее и
   показываются отдельно, с автором и причиной.
3. **Редкость настоящая.** Меньше уровней, выше пороги. Часть вещей нельзя
   «нафармить» — их только вручают.
4. **Без тёмных паттернов.** Убираем «время на сайте» и все секреты.
5. **Витрина, а не список.** Страница — зал трофеев с артом и иерархией, а не
   таблица метрик.
6. **Мессенджер не трогаем** — личная переписка вне скоупа.
7. **Каталог в Go — источник правды**, БД-таблица `achievements` — зеркало.

## Решения (согласовано)

- **Назначение:** статус/престиж, идентичность/родство, память о событиях.
- **Аудитория:** и для себя (гордость), и напоказ (витрина для других).
- **Гибрид:** авто-вехи + ручные награды; авто — микс количества и качества.
- **Ручные:** вручает админ и модераторы (UI в `apps/dev-dashboard`).
- **Ивенты/номинации:** потом (не сейчас).
- **Титулы/статусы** (Основатель, Staff, Ветеран, Донатер): отдельная сущность, не сейчас.
- **Без гармы:** слагаемое наград убирается из формулы `RecomputeUserProfileStats`
  (и `session_time/30` — вместе с самой группой). Просадку принимаем.
- **Секреты:** выпиливаем полностью.
- **Приватность:** один флаг `private_hide_achievements` скрывает весь блок наград.
- **Момент получения:** уведомление **в панель уведомлений, без тостов** — для
  **всех** наград (и авто, и ручных).
- **Закрытые награды:** показываем **только открытые**; ещё не полученные не
  светим (ни силуэтов, ни прогресса).
- **Арт:** у каждой награды свой нарисованный трофей.
- **Серии уровней:** веха — это серия уровней (Замеченный → Популярный → …),
  каждый уровень = отдельный трофей со своим процентом.
- **Повторные ручные награды:** можно, с историей (каждая выдача — своя строка).
- **На профиле:** топ по редкости (автоматически, без ручного пина).
- **У ручной награды показываем** автора, причину и дату.
- **Старые достижения:** чистый старт.
- **Масштаб:** мало и метко (единицы–два-три десятка).
- **Косметика** (титул/значок/цвет ника): позже.

## Редкость — реальный процент владельцев

Редкость не ярлык, а **живая метрика**: доля аудитории, владеющая наградой
(уровнем). Честная и самообновляющаяся.

- Формула: `owners / base · 100`, округление до сотых (фронт показывает одну цифру).
- **База `base` — активные** (MAU-подобно): пользователи, заходившие за последние
  **90 дней** (`user_daily_visits`). Заброшки не раздувают знаменатель. Если
  активных нет — фолбэк на всех (никогда не делим на ноль).
- Владельцы тоже считаются только среди активных, поэтому процент ≤ 100.
- **Хранение:** `achievements.owner_share` — JSON `{"1": 3.42, "2": 1.1, …}`
  (уровень → процент). Синк эту колонку не трогает. (Имя `owner_share`, а не
  `rarity`, потому что легаси-колонка `rarity VARCHAR` уже существует.)
- **Обновление:** фоновый воркер раз в **6 часов** + один раз на старте + после
  бэкфилла. Не на лету.
- У ручных наград — тоже процент (вручили двоим = очень редко).
- **Стаж** — динамическая серия: воркер считает уровни **1…31** (до 30 лет),
  границы по `created_at <= NOW() - INTERVAL`.
- Показывается **только числом**, на каждом трофее/карточке.

Сигналы для «качественных» вех, которые реально есть в данных:
лайки (треды/посты/стена), число ответов (постов в треде, комментов стены),
просмотры постов стены, репосты, подарки, число участников g-саба (для
владельца), возраст аккаунта, интеграции.

## Модель (согласована)

Каталог получает `kind`:

- `milestone` — авто. `stat` (`counter`/`derived`), `levels[]` (threshold,
  name/description-ключи). Без награды. Особый случай — **стаж** (динамическая
  серия, уровни не перечисляются).
- `award` — ручная. `title/description`-ключи, `icon`, `origin` (`code`/`admin`),
  опционально `image_url` (у админских). Уровней нет; уровень всегда 1.

Редкость — не поле, а вычисляемый процент владельцев (см. выше).

## Изменения данных

- **`user_awards`** (новая таблица, ручные награды с историей отзыва):
  ```sql
  CREATE TABLE user_awards (
      id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
      user_id       UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
      award_key     TEXT NOT NULL,
      awarded_by    UUID REFERENCES users(id) ON DELETE SET NULL,
      reason        TEXT NOT NULL DEFAULT '',
      awarded_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
      revoked_at    TIMESTAMPTZ,
      revoked_by    UUID REFERENCES users(id) ON DELETE SET NULL,
      revoke_reason TEXT NOT NULL DEFAULT ''
  );
  ```
  Активные выдачи = `revoked_at IS NULL`; повторные выдачи — отдельными строками.
- `achievements` + `kind TEXT`, `origin TEXT`, `image_url TEXT` (миграция 114).

## Каталог: авто-вехи (согласовано)

Без тривиальных уровней — каждая награда заметно редкая. «Хиты» схлопнуты в один
композитный «Резонанс» (сырые хиты провоцируют накрутку).

| Тема | Уровни (порог — название) |
|---|---|
| **Записи** (треды + посты стены) | 25 «Писец» · 100 «Хронист» · 500 «Архивариус» |
| **Лайки полученные** | 50 «Любимец» · 250 «Кумир» · 1000 «Идол» |
| **Стаж аккаунта** (динамическая серия) | с полугода, без предела; имя = срок («1 год на g6», «2 года на g6», …) |
| **Резонанс** (композит, лучший контент за всё время) | 100 «Волна» · 500 «Шторм» · 2000 «Цунами» |

**Резонанс** = `uniq-лайки·1 + uniq-комментаторы·3 + uniq-репостеры·5`, считается
по **уникальным людям** (один человек — один вклад каждого типа), берётся лучший
результат за всю историю. Просмотры в формулу не входят: у тредов их нет вообще,
а у стены они есть только отдельным сигналом (тему пока не берём).

**Стаж** — единственная динамическая серия: уровень = сколько полных периодов
(0,5 года, затем каждый год) пользователь на сайте, уровням нет предела. Требует
спец-обработки в движке и фронте (не статический список уровней).

Итого авто: ~9 наград + уровни стажа.

## Ручные награды (согласовано)

- **Фиксированные + создаваемые админом.** Стартовые 6 наград заданы в Go; админ
  может создавать новые прямо из панели — они сохраняются в БД и становятся
  постоянными (каталог становится гибридным: `origin = code | admin`).
- **Стартовые 6:** «Ктитор» (вклад в проект) · «Баг-хантер» · «Зодчий»
  (творчество) · «Хранитель» (поддержка сообщества) · «Патриарх» (высшая честь) ·
  «Триумфатор» (события; механизм ивентов — позже). Названия/арты финальны,
  арты рисуются позже.
- **Редактирование:** название/описание/арт можно править. **Удалить** — только
  если награду ещё никому не вручали (иначе история выдач сохраняется).
- **Отзыв:** выдачу можно отозвать (с историей: выдан → отозван, кто/когда/почему).
- **Панель:** `apps/dev-dashboard` — создание/редактирование наград, выдача,
  отзыв, список выдач, загрузка картинок.
- **Картинки:** загружаются файлом в S3 (Garage), URL хранится в БД.

## Модель данных (уточнено)

- `achievements` + `origin TEXT` (`code`/`admin`), + `kind TEXT`
  (`milestone`/`award`), + `image_url TEXT` (админские награды; у code-наград арт
  может жить реестром во фронте).
- Go-`Sync` управляет только строками `origin = code` (upsert + удаление
  снятых с каталога). Строки `origin = admin` синк не трогает.
- `user_awards.award_key` ссылается на `achievements.group_key`.

## API

- `GET /api/v1/user_awards?user_id=eq.<id>` — публично, тем же правилом
  приватности, что и достижения (`private_hide_achievements`); владелец видит
  всегда, модераторы/админы обходят флаг. Отдаёт только активные выдачи
  (`revoked_at IS NULL`) с вложенным объектом награды (`image_url`, `rarity`, …).
- `GET /api/v1/achievements` — каталог (зеркало, включая `origin` и `rarity`).
- Admin (staff: `moderator`/`admin`, все пути статические — gin не конфликтует):
  - `POST   /api/v1/admin/awards` — создать награду (тело: `key?`, `title`,
    `description`, `icon`, `image_url`, `sort_order`); ключ генерируется, если пуст.
  - `PATCH  /api/v1/admin/awards` — править (тело с `key`); только `origin=admin`.
  - `DELETE /api/v1/admin/awards?key=…` — удалить, только если выдач нет.
  - `POST   /api/v1/admin/awards/image` — загрузка арта (multipart `key`+`file`)
    в публичный бакет `awards` под уникальным ключом `<uuid>` (cache-busting).
  - `POST   /api/v1/admin/awards/grant` — выдать (`user_id`, `award_key`, `reason`).
  - `POST   /api/v1/admin/awards/revoke` — отозвать (`id`, `reason`), soft с историей.
- **Уведомления** (в панель, без тостов): `achievement_unlock` при росте уровня вехи
  (движок зовёт `Notifier` только при фактическом повышении → идемпотентно) и
  `award_granted`/`award_revoked` при выдаче/отзыве — после успешного коммита,
  чтобы не было фантомных нотификаций.

## Страница (зал трофеев)

- Шапка: профиль, «N наград».
- **Витрина** — все открытые награды (вехи-уровни + ручные), редчайшее первым
  (крупные трофеи, блеск); процент владельцев на каждой.
- **Ручные** — отдельным блоком, с автором, причиной и датой.
- Показываем **только открытое** — ни силуэтов, ни прогресса для неоткрытого.
